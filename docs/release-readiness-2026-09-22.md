Baton release review, 22 September 2026
======================================

Reviewed commit `730c61d`, version `0.2.3`, with an initially clean working tree. This covers the current codebase, including execution, routing, discovery, CLI/MCP, persistence, installation, release tooling, sharing service and documentation. It is a review and implementation plan. Application source has not been changed.

I would remove adapter approval completely. The current system makes an agent hand control back to the user to copy a digest into a terminal, while the same agent may already execute arbitrary commands on that machine. The code itself acknowledges that the terminal check is not a security boundary. A public release should make delegation work with the installed accounts, without an adapter ceremony or a mandatory interview about model ratings.

The core is worth retaining. Declarative argument arrays, account affinity, process-group cleanup, SQLite transactions, failover limited to admission failures, and the existing artifact tests solve concrete problems. There is no need for a rewrite. However, several correctness defects remain, including ones the passing tests do not cover.

**Confirmed execution and routing defects.**

The [reproduction script](review-2026-09-22/reproduce.ts) exercises the actual supervisor, registry, executor and temporary SQLite stores. It uses fake executables and injected execution results, never real model calls. [Recorded observations](review-2026-09-22/observations.jsonl) contain the outputs. Run it with `bun docs/review-2026-09-22/reproduce.ts`. P1 means fix before release; P2 means a concrete defect or limitation that should be scheduled before calling the affected feature polished.

1. **P1. Two active turns can write the same resumed session.** The guard searches for an active run with the same immediate `resumed_from` ID. Complete A, complete its continuation B, start a continuation of B, then resume A again. Both new runs are admitted and remain `running`, although their session handle is identical. The direct-sibling test passes and misses this ancestor case. Reserve the actual session identity across processes, including app, account and session handle, inside the admission transaction. Release the reservation only after the process has stopped. [Source](/Users/daniel/Work/model-router/src/supervisor/supervisor.ts:859).

2. **P1. An output error can disappear and become success.** `errorWhen` examines JSONL records retained in the final stdout tail. A fake CLI emitted an error event, more than one million bytes of diagnostics, then a text event. Baton returned `ok: true` and `partial answer`. Work-start markers already survive the whole stream, but terminal errors do not. Parse relevant events incrementally and retain the failure independently of the diagnostic buffer. The same bounded parser should retain the selected answer and session handle. [Source](/Users/daniel/Work/model-router/src/adapters/executor.ts:267).

3. **P1. Canaries bypass the configured permission ceiling.** Both discovered and built-in canaries select the least permission level the adapter supports, without applying `max_autonomy:<app>`. With a readonly ceiling and a full-only fake adapter, the canary executor received `full`. Put diagnostic executions through the same account, block and permission checks as ordinary runs. Removing human approval must also remove this separate execution policy. [Discovered canary](/Users/daniel/Work/model-router/src/discovery/discovery.ts:679), [built-in canary](/Users/daniel/Work/model-router/src/cli/cli.ts:1012).

4. **P1. The standard macOS build produces an unusable artifact here.** On macOS arm64 with Bun 1.4.0, `bun run build` succeeded, but the rebuilt executable exited 137. `codesign --verify --verbose=2 dist/baton` reported an invalid signature. After `codesign --force --sign - dist/baton`, verification, all ten binary tests and the release smoke check passed. Signing is already handled by installation, self-update and release verification, but is missing from the normal build used by local validation and macOS CI. Centralize artifact finalization and verify the executable before declaring the build successful. This finding concerns the local build path; it does not establish that the published release downloads are broken. [Build command](/Users/daniel/Work/model-router/package.json:16), [existing signing helper](/Users/daniel/Work/model-router/src/cli/update.ts:172).

5. **P2. Failover leaves metadata belonging to the wrong adapter.** The supervisor updates `runs.app`, `slug` and `instance` when it switches targets, but keeps the first adapter's version, digest and resolved options in `runs.options`. A simulated run failed admission on adapter A, succeeded on adapter B, then could not resume because Baton compared B against A's version. Store the execution metadata on each attempt and resume from the answering attempt. Also inherit its resolved permissions and timeout, not the first attempt's. [Source](/Users/daniel/Work/model-router/src/supervisor/supervisor.ts:726).

6. **P2. Named accounts receive the wrong model catalog.** Catalog enumeration reads the parent process's environment, before a named instance's overlay is applied. A fake paid account offered `paid-model`, but `listModels` attributed `default-model` to that account and selecting `paid-model` failed as unknown. Enumerate models with each relevant account's effective environment and cache by that environment's identity/configuration. A provider's model availability must stay attached to the account that reported it. This reproduction establishes incorrect discovery and availability, not cross-account credential execution. [Source](/Users/daniel/Work/model-router/src/registry/catalog.ts:71), [listing process](/Users/daniel/Work/model-router/src/registry/catalog.ts:156).

7. **P2. Permission filtering checks the ceiling instead of the requested execution level.** A readonly-only adapter is unusable under the default `full` ceiling, even when the caller explicitly requests readonly. The reproduction receives `ceiling 'full' unsupported`. Resolve the requested/default level against the ceiling first, then check whether the adapter supports that result. Apply the same calculation to listings and execution. Report supported permission levels in `list_models` so agents can choose a compatible route. [Source](/Users/daniel/Work/model-router/src/registry/registry.ts:406).

8. **P2. Failed result storage leaves an immortal running record.** The settlement path deletes the live entry, catches a failed database commit, and resolves without reporting the storage failure. A SQLite trigger simulating a failed result write left the run `running` after its `settled` promise resolved. Recovery still skipped it because the owner process was alive. Propagate and log the failure, keep enough pending outcome state to retry, and reconcile completed processes within a live supervisor. An MCP caller should receive an actionable persistence error instead of polling forever. [Source](/Users/daniel/Work/model-router/src/supervisor/supervisor.ts:546).

9. **P2. Model discovery blocks active execution timers.** Version and catalog probes use `spawnSync` in the server process. A fake catalog sleeping 200 ms delayed a 10 ms timer to 445 ms in the recorded run. Real catalog probes allow 15 seconds each and run serially across adapters. During that time the process cannot service run timeouts, drain output or answer other requests. Use asynchronous, deduplicated probes with bounded concurrency and cache refresh. This is about the server event loop, not the speed of SQLite queries. [Catalog source](/Users/daniel/Work/model-router/src/registry/catalog.ts:153), [version source](/Users/daniel/Work/model-router/src/registry/registry.ts:203).

10. **P2. Retention is only enforced when the database opens.** A store opened with a run cap of two retained five completed runs without reopening. A long-lived MCP or HTTP server can therefore exceed the advertised roughly 2,000-run buffer indefinitely. Prune after a bounded number of completions or on a maintenance interval, keeping active runs and aggregate evidence. Consider a byte budget too, since the count alone does not bound stored prompt size. [Source](/Users/daniel/Work/model-router/src/store/store.ts:248).

11. **P2. Adapter upgrade behavior depends on running a diagnostic command.** `detectDiscovered` marks an adapter stale, but only CLI `detect` calls it. Ordinary routing, MCP listing and `detectApps` do not. An upgraded adapter can continue working until somebody runs `baton detect`, which disables it and requires a manual canary. The reproduction records `active` before explicit detection and `stale` afterward. Replace this lifecycle with availability plus diagnostic results. Version changes should invalidate caches and recorded health, not require a user to restore permission to run. [Detection](/Users/daniel/Work/model-router/src/discovery/discovery.ts:789), [CLI call site](/Users/daniel/Work/model-router/src/cli/cli.ts:240).

**User-facing hoops to remove.**

| Current behavior | Proposed behavior |
| --- | --- |
| `register_app` quarantines, the user reviews a digest, and a TTY-only command approves it. | Valid registration makes an adapter eligible immediately. No review/approve commands, digest copying or terminal test. |
| Re-registering identical content disables an active adapter. The MCP tool advertises itself as idempotent. | Identical registration is a no-op. Invalid replacements preserve the working adapter. |
| A paid canary with an exact `BATON_CANARY` response is required for activation. | Testing is optional and callable by the agent. Store its result as diagnostic evidence. Normal registration does not spend a model call. |
| Literal JSON and other shell punctuation are rejected in argument elements, even though execution never uses a shell. | Validate the actual argument/template contract and reject NUL. Permit literal JSON and punctuation; escape values when displaying them. The reproduction rejects a normal `--settings '{"mode":"normal"}'` argument. |
| The installed evaluation appendix instructs the agent to interview the user, normalize priors, obtain another explicit yes, and discuss account preciousness. | Start unrated and use neutral defaults. Capture ratings when useful. An explicitly requested preference change is enough authorization; no mandatory interview or numerical confirmation loop. |
| `profile import` exits successfully without importing until it is rerun with `--yes`, then may require another command to activate. | Import by default, with `--dry-run` for preview. Activate the first profile automatically. Keep later profile switching explicit and make replacement reversible with a saved previous version. |
| Resume can only reduce the original permissions and timeout. | Inherit omitted options; honor explicitly changed options within the current configured ceiling. A review can be followed by implementation in the same session. |
| A resume requested at full permissions with a 5,000 ms budget silently stayed readonly with its original 50 ms budget in the reproduction. | Return the actual resolved options and any constraint in the response. Give each turn its requested budget. |
| `adapters reject` means a route block for built-ins and a spec state for discovered adapters. | Use one enable/disable mechanism with consistent semantics. An explicit block survives spec updates. |
| Help for every command prints the entire reference. Successful CLI runs print the answer without the handle needed to inspect or grade them. | Command-specific help; print run ID and progress to stderr; keep answer output clean; add structured output for scripts. |
| Long-running MCP work has no exposed cancel tool, despite internal cancellation support. There is no CLI cancel command either. | Add `cancel_run` and `baton cancel <id>`, including cancellation handled by the owning supervisor when the request comes from another process. |
| `baton update` changes the executable but does not refresh copied host skills. | Refresh existing Baton-owned skill installations during update, preserving host configuration and unrelated instructions. Users should not need to remember a second reinstall command. |

Relevant sources are [approval](/Users/daniel/Work/model-router/src/cli/cli.ts:735), [registration](/Users/daniel/Work/model-router/src/discovery/discovery.ts:431), [argument validation](/Users/daniel/Work/model-router/src/discovery/discovery.ts:295), [evaluation instructions](/Users/daniel/Work/model-router/src/cli/templates/eval.md:18), [imports](/Users/daniel/Work/model-router/src/cli/cli.ts:1495), [resume options](/Users/daniel/Work/model-router/src/supervisor/supervisor.ts:1045), [help](/Users/daniel/Work/model-router/src/cli/help.ts:1), and [update](/Users/daniel/Work/model-router/src/cli/update.ts:66).

Host-owned trust prompts and sign-in to publish a profile are different. Baton should explain them when encountered, while keeping optional sharing outside the normal delegation path. Account blocks, configured permission ceilings, process cleanup, and the rule against automatic replay after work starts should remain enforced without new confirmation screens.

**Complexity that can be deleted or contained.**

The discovery module is 981 lines and the CLI is 2,207 lines. Removing the approval lifecycle will delete real behavior, messages and tests across both, the registry, MCP definitions and docs. Do that before dividing the remaining CLI into small command modules. Keep transport formatting separate from shared operations such as registering an adapter, resolving a run and recording a grade. Avoid a new command framework unless the remaining code actually needs one.

The automatically maintained `ratings.yaml` file is another large source of avoidable complexity. It is never read for routing, yet it has a publication lock, revision protocol, digest, repair path and tests. Prefer generating a consistent ratings export on demand. SQLite already owns the data; a permanent second representation should exist only if a supported consumer needs it. [Publication implementation](/Users/daniel/Work/model-router/src/eval/publish.ts:18).

`AdapterSpec` and the Zod adapter schema are maintained separately. The one-way assignment check only proves the parsed object can be used as an adapter; it is not an exact equivalence check. Make the validated schema authoritative and derive its TypeScript type. Keep runtime validation at registration boundaries instead of repeatedly defending the same stored shape throughout routing.

The shipped skill also prescribes too much personal workflow: mentioning the word Baton triggers delegation, workers are told to delegate again, fixed model rankings are described as the user's priors, and long instructions repeat polling and grading rules. Shorten it around when to delegate, how to provide context, how to wait/cancel, and how to evaluate a useful result. Get capabilities from `list_models`. Keep duels, prior seeding and pool tuning as optional advanced features. There is no need to discard the rating mathematics merely because it is sophisticated.

**Public service and release packaging.**

The sharing service needs additional work if it is part of this launch. The anonymous device-code endpoint uses a global limit of 500 pending requests. One client can occupy all slots for the 15-minute expiry window; the count and insert are also separate operations. Use per-client throttling and an atomic capacity check. Profile uploads are bounded per request but there is no account-wide profile/storage limit and listings are unpaginated. Add server-enforced limits and pagination without adding another user approval flow. These findings come from code inspection, not a load test against the public site. [Device endpoint](/Users/daniel/Work/model-router/site/src/pages/api/device/code.ts:9), [profile storage](/Users/daniel/Work/model-router/site/src/lib/db.ts:219).

The repository has no tracked license, contributing guide, security reporting instructions or changelog. Add those before the public launch. Document the supported host/version matrix and known limitations. The website's D1 configuration still contains a placeholder database ID; production configuration and an actual end-to-end sign-in/share/revoke check remain release work. The existing production smoke checks exercise a local built Worker, not the deployed service.

Correct the privacy wording too. The homepage says Baton does not send prompts anywhere. Delegated CLIs receive those prompts and may send them to their model providers. Say that Baton stores local run history and that the optional sharing service receives rating profiles rather than run prompts. Move the old v0.1.0 recovery material out of the main installation path, and remove every approval reference from the README, website, tools and generated skills in the same change. [Homepage](/Users/daniel/Work/model-router/site/src/pages/index.astro:160).

**Implementation order and acceptance checks.**

1. **Remove the adapter approval lifecycle.** Replace five lifecycle states with enabled/disabled configuration plus separate diagnostic results. Registration validates and stores an immutable revision; unchanged submissions do nothing. Keep internal revision matching for concurrent edits, with no digest exposed as a user obligation. Migrate active/approved records to enabled, validate pending/stale records for eligibility without background model calls, and preserve rejected adapters as disabled. Missing binaries produce a normal availability reason. Delete approval commands and instructions together. Acceptance: an agent registers and runs a valid adapter without a terminal, canary or human reply; retries preserve usability; invalid replacements and explicit blocks behave predictably.

2. **Fix execution correctness.** Add session reservations, attempt-owned execution metadata, streaming error retention and visible handling of failed result commits. Route optional adapter tests through shared execution policy. Allow explicit resume option changes within the configured ceiling. Acceptance: ancestor resumes cannot overlap; failover results resume on the actual answering target; errors survive arbitrarily long diagnostics; a failed result write never appears indefinitely healthy and running; canaries obey blocks and permissions.

3. **Fix discovery and long-lived operation.** Enumerate per account, make probes asynchronous, check resolved permission levels, and enforce ongoing retention. Expose supported levels, catalog freshness and useful failure reasons. Acceptance: two accounts with different catalogs advertise and select their own models; a slow listing does not stall an existing run's timer or output; readonly-only adapters work under a full ceiling; a daemon remains within retention policy without restarting.

4. **Simplify the normal workflow.** Remove default rating interviews and confirmation language. Make import do what its name says, refresh installed skills on update, add command-specific help, run handles, structured output and cancellation. Default setup should guide the user to a first successful delegation; accounts/pools, duels, priors and sharing can be configured later. Acceptance: install, discover, delegate, inspect, cancel and continue work without an unrelated setup conversation or undocumented terminal repair.

5. **Finish and verify the release.** Finalize/sign binaries through one build path, pin the tested Bun version in CI, add repository release documents, and run checks against the actual artifacts on all four supported OS/CPU combinations. Add focused regression cases from this review. Verify the documented permission levels and resume behavior with an opt-in live matrix for every built-in adapter. Either finish the sharing service's limits and deployed smoke checks or keep it explicitly outside the core release commitment. Acceptance: the documented build/install/update path works from a clean environment without manual signing, and installed skills contain the new workflow.

These are focused changes suitable for several reviewable PRs. The broadest risk is changing execution semantics while removing approval, so the session, failover and permission regressions should accompany those changes. A configurable approval mode, a replacement trust wizard, or a large new plugin abstraction would preserve the complexity the release is meant to remove.
